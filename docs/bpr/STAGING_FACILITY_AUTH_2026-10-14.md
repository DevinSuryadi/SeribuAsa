# Verifikasi Faskes dan batas otorisasi staging

- Akun Faskes baru tetap berstatus `pending`. API operasional keluarga, asesmen, katalog, dan pesanan sekarang memerlukan Faskes `approved`. Faskes dapat melihat statusnya melalui `/facilities/me` dan dashboard. Admin dapat menyetujui/menolak melalui `/admin/facilities` dengan aktor, waktu, dan alasan penolakan tersimpan.
- Peran `admin`/`government` untuk API backend hanya diterima dari `app_metadata` Supabase yang dikelola server. `user_metadata` dan alamat email tidak lagi dapat menaikkan hak akses. Signup publik menolak peran istimewa dan mengikat pembuatan profil ke ID sesi yang terverifikasi. Mock auth perlu `DEV_MODE=true` secara eksplisit dan hanya tersedia dengan database SQLite lokal tanpa mode pembayaran produksi.
- **Langkah rilis sebelum mengaktifkan migrasi:** audit akun Admin yang sah. Bila saat ini hak Admin hanya tersimpan pada `user_metadata`, pengelola Supabase perlu menetapkan `app_metadata.role=admin` melalui kredensial layanan tepercaya. Jangan memindahkan seluruh nilai `user_metadata` secara massal; verifikasi identitas dan otoritas masing-masing akun. Perubahan itu tidak dilakukan oleh kode atau tes ini.
- Migrasi `a20261014allocation` juga menambah jejak review Faskes. Akun Faskes lama dengan status `approved` tetap dapat bekerja; akun `pending` menunggu tinjauan. Migrasi tidak mengubah status akun lama secara otomatis.
- Verifikasi otomatis: tes backend mencakup penolakan peran Admin palsu, signup peran istimewa, dev auth yang tidak aktif tanpa opt-in, dan persetujuan Faskes. Pengujian sesi Supabase nyata serta konfigurasi akun Admin staging masih perlu dilakukan sebelum rilis.
