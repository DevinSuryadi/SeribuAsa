1. API STRUCTURE
   Location: apps/backend/app/api/
   Framework: FastAPI with SQLAlchemy ORM
   Authentication: Supabase JWT (production) / Mock auth (development)
   Prefix: /api/v1 (all routes registered under this prefix)
   
   Router Files Found:
   - fies.py (FIES survey endpoints)
   - nutrition.py (Nutrition measurement endpoints)
   - users.py (User profile endpoints)
   - donations.py (Donation management)
   - products.py (Product catalog)
   - orders.py (Order management)
   - auth.py (Authentication)
   - vouchers.py (Voucher management)
   - recommendations.py (Recommendation engine)
   - reports.py (Reporting)
   - settlements.py (Vendor settlements)

2. EXISTING FIES ENDPOINTS (apps/backend/app/api/fies.py)
   
   Current Endpoints:
   - POST /fies/submit (Status 201)
     - Submit FIES survey (beneficiary only, days 1-7 of month)
     - Prevents duplicates within same month
     - Returns: survey_id, score, classification, next_available_date
   
   - POST /fies/calculate (No auth)
     - Calculate FIES score from raw responses
     - Returns: score, classification, classification_display, recommendations
   
   - GET /fies/history/{beneficiary_id}
     - Fetch all historical FIES surveys
     - Authentication required
     - Returns: List of surveys with trend analysis
     - Includes: score_change, improving flag, previous_classification

3. EXISTING NUTRITION ENDPOINTS (apps/backend/app/api/nutrition.py)
   
   Current Endpoints:
   - GET /nutrition/children
     - List all children of authenticated beneficiary
     - Returns: List of ChildResponse with age_months calculated
   
   - POST /nutrition/measurements (Status 201)
     - Add new nutrition measurement for a child
     - Calculates WHO Z-Scores automatically
     - Validates child ownership
     - Returns: NutritionMeasurementResponse
   
   - GET /nutrition/measurements/{child_id}
     - Fetch all measurements for a child with growth analysis
     - Validates child ownership
     - Includes trend analysis: "improving", "stable", "declining"
     - Returns: Comprehensive NutritionHistoryResponse with chart data
   
   - POST /nutrition/zscore (No auth)
     - Calculate WHO Z-Score from raw measurements
     - Returns: ZScoreResponse with classifications

4. DATABASE MODELS
   
   FIESSurvey Model (apps/backend/app/models/nutrition.py):
   - beneficiary_id (UUID, FK to beneficiary_profiles)
   - responses (JSONB - 8 question responses)
   - score (Integer 0-8)
   - classification (String: food_secure|moderate|severe)
   - survey_date (DateTime, indexed)
   - survey_month (Integer 1-12)
   - survey_year (Integer)
   - Indexes: idx_fies_survey_beneficiary_period
   
   NutritionMeasurement Model (apps/backend/app/models/nutrition.py):
   - child_id (UUID, FK to children)
   - measurement_date (Date, indexed)
   - weight (Numeric 5,2 in kg)
   - height (Numeric 5,2 in cm)
   - muac (Numeric 5,2 optional, in cm)
   - z_score_weight (Numeric 5,2)
   - z_score_height (Numeric 5,2)
   - z_score_weight_height (Numeric 5,2)
   - classification (String)
   - Indexes: idx_nutrition_measurement_child_date
   
   Child Model (apps/backend/app/models/user.py):
   - beneficiary_id (UUID, FK to beneficiary_profiles)
   - full_name (String)
   - date_of_birth (Date)
   - gender (Enum: male|female)
   - relationships: nutrition_measurements

5. PYDANTIC SCHEMAS
   
   FIES Schemas (apps/backend/app/schemas/fies.py):
   - FIESResponse: Full survey with all fields
   - FIESHistoryItem: Minimal survey fields
   - FIESSurveyTrend: Trend analysis
   - FIESSurveyHistoryResponse: History with trend
   - All use: model_config = ConfigDict(from_attributes=True)
   
   Nutrition Schemas (apps/backend/app/schemas/nutrition.py):
   - NutritionMeasurementResponse: Full measurement data
   - ChildInfo: Child metadata
   - NutritionHistoryResponse: History with child and chart data
   - GrowthChartData: WHO reference and trend
   - All use: model_config = ConfigDict(from_attributes=True)

6. AUTHENTICATION & AUTHORIZATION
   
   Location: apps/backend/app/middleware/auth.py
   
   Modes:
   - Production: JWT validation via Supabase
   - Development: Mock authentication (if DEV_MODE env var set)
   
   Key Functions:
   - get_current_user(): Returns AuthenticatedUser (required auth)
   - OptionalAuth(): Returns AuthenticatedUser or None
   - RequireRole(allowed_roles): Role-based access control
   
   AuthenticatedUser Fields:
   - user_id (string, from UUID)
   - email
   - role (donor|beneficiary|vendor)
   - email_verified (bool)
   
   HTTP Status Codes for Auth:
   - 401: Unauthorized (invalid/missing credentials)
   - 403: Forbidden (insufficient permissions)
   - 500: Auth service error

7. ERROR HANDLING PATTERNS
   
   HTTP Status Codes Used:
   - 200: OK (GET/PATCH success)
   - 201: Created (POST success)
   - 400: Bad Request (validation/logic errors)
   - 404: Not Found (resource doesn't exist)
   - 409: Conflict (duplicate/conflicting state)
   - 500: Internal Server Error (unexpected errors)
   
   Pattern: FastAPI HTTPException
   raise HTTPException(
       status_code=status.HTTP_404_NOT_FOUND,
       detail="Resource not found"
   )
   
   Examples from Code:
   - 404: "User profile not found", "Child not found or not yours"
   - 409: "Sudah mengisi survei bulan ini" (Already filled this month)
   - 400: Validation errors, bad input

8. RESPONSE WRAPPER PATTERNS
   
   Pattern 1 - Success Wrapper:
   {
       "success": true,
       "data": {
           "id": "...",
           "score": 5,
           "classification": "moderate"
       }
   }
   Used in: FIES submit/calculate/history, nutrition zscore/history
   
   Pattern 2 - Direct Model Response:
   Decorated with @router.post(..., response_model=Model)
   Returns the Pydantic model directly
   Used in: POST endpoints with response_model defined
   
   Pattern 3 - HTTP Exceptions:
   {"detail": "Error message"}
   Automatically formatted by FastAPI

9. QUERY PATTERNS FOR "LATEST" RECORDS
   
   Current Pattern in Nutrition (line 138-142):
   measurements = (
       db.query(NutritionMeasurement)
       .filter(NutritionMeasurement.child_id == child_id)
       .order_by(NutritionMeasurement.measurement_date.desc())
       .all()
   )
   latest = measurements[0]  # First element is latest
   
   FIES Service Pattern (line 135-139):
   surveys = (
       db.query(FIESSurvey)
       .filter(FIESSurvey.beneficiary_id == beneficiary_id)
       .order_by(FIESSurvey.survey_date.desc())
       .all()
   )
   latest = surveys[0]  # First element is latest
   
   Optimized Pattern (Recommended for Single Latest):
   latest = (
       db.query(Model)
       .filter(Model.field == value)
       .order_by(Model.date_field.desc())
       .first()  # <- Gets only the latest
   )

10. EXAMPLE GET ENDPOINTS EXAMINED
    
    Single Resource Gets:
    - GET /users/{user_id}: Simple query + 404 check
    - GET /products/{product_id}: Query + relationship enrichment
    - GET /donations/{donation_id}: Query + ownership validation
    
    History/Multiple Gets:
    - GET /nutrition/measurements/{child_id}: All measurements + trend analysis
    - GET /fies/history/{beneficiary_id}: All surveys + trend calculation
    
    Common Pattern:
    1. Query with filter(s) + order_by().desc()
    2. Check if results exist (404 if not)
    3. Build response using Pydantic schemas
    4. Return {"success": true, "data": {...}} or direct model
    5. Handle ownership validation where needed
