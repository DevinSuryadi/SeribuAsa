KEY FINDINGS
================================================================================

1. SCOPE OF MERGER
   - DompetNutrisi.tsx: 473 lines | Shows wallet balance + transaction history
   - OrderHistoryPage.tsx: 582 lines | Shows purchase order history + filters
   - Both at beneficiary role | Both use DashboardLayout wrapper
   - Combined: 1,055 lines → Mergeable into 800-900 lines post-refactoring

2. DATA STRUCTURE DIFFERENCES
   ┌─────────────────┬─────────────────────────┬─────────────────────┐
   │ ASPECT          │ WALLET (Dompet)         │ ORDERS              │
   ├─────────────────┼─────────────────────────┼─────────────────────┤
   │ Primary Data    │ Balance + Transactions  │ Orders + Metadata   │
   │ API Calls       │ 3 parallel (all-or-one)│ 1 reactive (filter) │
   │ Pagination      │ 20 items (no UI)       │ 10 items + UI       │
   │ Filters         │ None (manual refresh)  │ Status + date range │
   │ KPI Display     │ Inline (3 values)      │ 3-card grid         │
   │ Sub-components  │ 0 (all inline)         │ 3 (Filters/QR/Card)│
   │ Memoization     │ None                   │ OrderCard memoized  │
   │ Modal           │ None                   │ QR Pickup Modal     │
   └─────────────────┴─────────────────────────┴─────────────────────┘

3. ARCHITECTURAL COMPATIBILITY
   ✅ Both use same UI framework (Tailwind + Lucide icons)
   ✅ Both use same shared utilities (formatIDR, formatDate)
   ✅ Both use same component library (Badge, Button, Skeleton)
   ✅ Both use similar error/loading patterns
   ✅ Both are lazy-loaded in routing
   ⚠️  Different state management patterns (parallel vs reactive)
   ⚠️  Different data fetching strategies
   ❌ No shared sub-components (OrderCard is order-specific)

4. RECOMMENDED MERGER APPROACH: TABBED INTERFACE
   
   Benefits:
   + Single route (/dashboard/activity)
   + Clear separation of concerns (tabs)
   + Mobile-friendly
   + Modal persistence across tabs (lift to parent)
   + Minimal refactoring needed
   - Requires tab state management
   - Slightly more complex than sectioned approach
   
   Alternative: Sectioned (vertical stack, simpler but less clear)

5. IMPLEMENTATION PHASES
   
   Phase 1: Create Tabbed Activity Page (2 days)
   └─ Extract logic from both pages into ActivityPage
     └─ Maintain current file structure, add tab UI
   
   Phase 2: Refactor Routes (1 day)
   └─ Add /dashboard/activity route
   └─ Redirect old routes with query params
   └─ Update navigation menu
   
   Phase 3: Optimize (1 day)
   └─ Memoize DompetNutrisi sections (like OrderCard)
   └─ Extract shared configs (statusMap, txTypeConfig)
   └─ Performance audit
   
   Phase 4: Deploy & Test (1 day)
   └─ Mobile/desktop testing
   └─ Filter/pagination testing
   └─ Action testing (QR, Reorder, etc.)
   
   TOTAL EFFORT: 5-6 days (conservative)

6. CRITICAL DECISIONS NEEDED
   
   [1] Route Strategy: Keep both routes or consolidate?
       → RECOMMENDED: Keep old routes, add redirects
   
   [2] Layout: Tabs, sections, or sidebar?
       → RECOMMENDED: Tabs (cleanest, most maintainable)
   
   [3] State: Keep useState or refactor to Context/Reducer?
       → RECOMMENDED: Keep useState (sufficient complexity)
   
   [4] File Organization: Single large file or split into sub-components?
       → RECOMMENDED: Start with single file (900 LOC is manageable)
   
   [5] Data Fetching: Fetch both tabs on mount or lazy-load?
       → RECOMMENDED: Lazy load based on active tab (performance)

7. RISK MITIGATION
   
   Risk: Breaking existing bookmarks/links
   → Mitigate: Keep old routes + redirects for 2+ releases
   
   Risk: Increased complexity in merged component
   → Mitigate: Start with single file, refactor if >1000 LOC
   
   Risk: Modal closing when switching tabs
   → Mitigate: Lift modal state to ActivityPage parent
   
   Risk: Performance degradation
   → Mitigate: Implement memoization + lazy loading + performance monitoring
   
   Risk: Regression in existing features
   → Mitigate: Automated tests for filters, pagination, actions, QR, reorder

8. SUCCESS CRITERIA
   
   ✓ All existing features preserved and working
   ✓ Mobile responsiveness maintained
   ✓ Performance not degraded (< 5% slower)
   ✓ QR modal works across tab switches
   ✓ Filters & pagination function normally
   ✓ Reorder action adds to cart correctly
   ✓ No console errors or warnings
   ✓ Old routes redirect seamlessly
   ✓ Unit tests pass (>80% coverage)
   ✓ E2E tests pass (happy path scenarios)
